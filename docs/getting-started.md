# Запуск проекта

Поддерживаемый сценарий локальной разработки работает через Docker Compose. PHP, Composer, Node.js, PostgreSQL и браузерное окружение для Panther устанавливать на хост не нужно.

Отдельный запуск с PHP, Composer, PostgreSQL и Node.js, установленными непосредственно в операционной системе, проектом не поддерживается: Makefile, CI, тестовые команды и браузерное окружение рассчитаны на Docker. Такой вариант технически можно собрать вручную, но он не является проверяемым контрактом проекта и поэтому здесь не документируется.

## Требования

Для обычной работы понадобятся:

- Git;
- Make;
- Docker с поддержкой Compose;
- Git LFS — рекомендуется при клонировании через Git; без него архив Chrome for Testing можно получить другими способами.

> [!NOTE]
> Make — обычная консольная утилита для Unix-подобных систем. На Linux и macOS проект удобно запускать напрямую из терминала. На Windows рекомендуемый вариант — WSL2 вместе с Docker Desktop.

## Первый запуск через Git LFS

| Команда | Что делает | Примечание |
|---|---|---|
| `git clone https://github.com/yaleksandr89/symfony-shop.git` | Клонирует репозиторий | |
| `cd symfony-shop` | Переходит в каталог проекта | |
| `git lfs install` | Подключает Git LFS | Обычно выполняется один раз для пользователя |
| `git lfs pull` | Загружает Chrome for Testing | Выполните до `make build` |
| `make init` | Создаёт `.env.docker` и локальные каталоги | Использует `.env.docker.example` и UID/GID пользователя хоста |
| `make build` | Собирает PHP-образ | |
| `make up` | Запускает `php`, `nginx` и `postgres` | |
| `make composer-install` | Устанавливает PHP-зависимости | Использует `composer.lock` |
| `make npm-install` | Устанавливает зависимости фронтенда | Использует `package-lock.json` |
| `make assets-build` | Собирает ресурсы фронтенда | |
| `make migrate` | Применяет Doctrine migrations | |
| `make demo-init` | Инициализирует демонстрационные данные | Только для локальных `dev`/`test` данных |

При стандартной конфигурации приложение доступно по адресу [http://localhost:8080](http://localhost:8080). Порт можно изменить через `APP_PORT` в `.env.docker`.

> [!WARNING]
> `make demo-init` пересоздаёт демонстрационные заказы. Используйте эту команду только для базы, данные которой можно заменить.

## Git LFS и Chrome for Testing

Panther использует Chrome for Testing, который устанавливается в PHP-образ при `make build`. Архив браузера хранится через Git LFS, а Chromedriver — обычным Git-файлом.

| Артефакт | Путь | Хранение |
|---|---|---|
| Chrome for Testing | `bin/chrome-linux64-150.0.7871.46.zip` | Git LFS |
| Chromedriver | `bin/drivers/chromedriver` | обычный Git |

Dockerfile ожидает ровно Chrome for Testing `150.0.7871.46`. Не заменяйте его текущей стабильной версией Chrome без одновременного изменения и проверки Docker/Panther-конфигурации.

Для зафиксированного архива подтверждены:

| Проверка | Ожидаемое значение |
|---|---|
| Размер | `186933179` байт |
| SHA-256 | `ad115a7498a17f53f6ed0914458326c6516addc756224db14c32184a9b1ab078` |

Получить этот архив можно тремя способами.

### Вариант 1 — Git LFS

Это рекомендуемый вариант для обычного `git clone`:

```text
git lfs install
git lfs pull
```

Официальный клиент и инструкции по установке: [git-lfs.com](https://git-lfs.com/).

### Вариант 2 — архив исходного кода GitHub

В настройках репозитория включено `Include Git LFS objects in archives`. Поэтому ZIP/tar-архив GitHub для нужной ветки или тега содержит сам архив Chrome, а не только указатель Git LFS.

Этот вариант удобен, если Git LFS устанавливать не хочется. Важно скачивать архив того же коммита или тега, с которым вы собираетесь работать: старый релиз может содержать другую версию проекта и другой набор браузерных файлов.

### Вариант 3 — официальный Chrome for Testing

Версия `150.0.7871.46` опубликована в официальном каталоге Chrome for Testing:

- [карточка версии `150.0.7871.46`](https://googlechromelabs.github.io/chrome-for-testing/150.0.7871.46.json);
- [официальный архив Chrome for Testing для Linux x64](https://storage.googleapis.com/chrome-for-testing-public/150.0.7871.46/linux64/chrome-linux64.zip).

Скачанный файл нужно сохранить под именем:

```text
bin/chrome-linux64-150.0.7871.46.zip
```

После ручной загрузки обязательно сверьте размер, SHA-256 и целостность ZIP с таблицей выше.

## Проверка архив Chrome

| Команда | Что проверяет |
|---|---|
| `git lfs ls-files` | Архив зарегистрирован в Git LFS, если используется LFS-сценарий |
| `wc -c < bin/chrome-linux64-150.0.7871.46.zip` | Размер файла |
| `sha256sum bin/chrome-linux64-150.0.7871.46.zip` | SHA-256 в Linux/WSL |
| `shasum -a 256 bin/chrome-linux64-150.0.7871.46.zip` | SHA-256 в macOS |
| `unzip -tq bin/chrome-linux64-150.0.7871.46.zip` | Целостность ZIP |

Если файл имеет размер около сотни байт и начинается со строки `version https://git-lfs.github.com/spec/v1`, в рабочей копии остался указатель Git LFS. Выполните `git lfs pull` либо замените указатель архивом, полученным одним из двух альтернативных способов выше.

После любой ручной замены архив должен давать тот же ожидаемый SHA-256. Если контрольная сумма отличается, не запускайте сборку и не коммитьте такой файл.

## Локальная конфигурация

`make init` создаёт `.env.docker` из `.env.docker.example`, подставляет текущие `HOST_UID` и `HOST_GID` и создаёт каталоги `var/cache`, `var/log` и `public/uploads`.

Если `.env.docker` уже существует, команда его не перезаписывает. Локальные секреты приложения и учётные данные OAuth храните не в `.env.docker`, а в `.env.local`.

> [!IMPORTANT]
> Значения из `.env.docker` передаются PHP-контейнеру как переменные окружения процесса и имеют приоритет над одноимёнными значениями из `.env.local`. Это особенно важно для настроек Panther, базы данных и любых ключей, которые случайно продублированы в обоих файлах.

Подробно слои окружения и их приоритет описаны в [руководстве по конфигурации](configuration.md#приоритет-переменных).

## Управление Docker

| Команда | Что делает | Примечание |
|---|---|---|
| `make ps` | Показывает контейнеры проекта | |
| `make restart php` | Перезапускает PHP | Также доступны `nginx` и `postgres` |
| `make log php` | Показывает журнал PHP в реальном времени | Также доступны `nginx` и `postgres` |
| `make log-all` | Показывает журналы всех сервисов | |
| `make in php` | Открывает Bash в PHP-контейнере от пользователя `app` | |
| `make down` | Останавливает окружение | том PostgreSQL сохраняется |

Полный список целей Make, включая тесты, проверки, покрытие и деструктивные команды, приведён в [руководстве по разработке](development.md#все-команды-make).

## Если первый запуск не удался

| Симптом | Что проверить |
|---|---|
| `make build` падает на распаковке Chrome | размер, SHA-256 и `unzip -tq` для архив Chrome |
| В Chrome-файле виден текст `git-lfs.github.com/spec/v1` | выполнен ли `git lfs pull` либо использован ли архив GitHub с включёнными объектами Git LFS |
| `.env.docker` отсутствует | выполнить `make init` |
| Контейнеры не стартуют | `make config`, затем `make ps` и `make log-all` |
| Приложение не открывается на `8080` | проверить `APP_PORT` в `.env.docker` и `make ps` |
| Изменение `.env.local` не сработало | проверить, не задан ли тот же ключ в `.env.docker` |

Правила почты, Messenger, OAuth, тестового окружения и остальных `.env*` собраны в [руководстве по конфигурации](configuration.md).
