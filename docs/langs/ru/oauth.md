# OAuth

## Выберите язык

| Русский | English | Español | 中文 | Français | Deutsch |
|---|---|---|---|---|---|
| **Русский** | [English](../en/oauth.md) | [Español](../es/oauth.md) | [中文](../zh/oauth.md) | [Français](../fr/oauth.md) | [Deutsch](../de/oauth.md) |

OAuth в Symfony Shop используется для входа и регистрации через внешний сервис, а также для явной привязки такого аккаунта к уже существующему локальному пользователю. Эти сценарии разделены: совпадение email само по себе не считается доказательством владения локальной учётной записью.

В этом документе:

- **провайдер** — внешний сервис входа, например Google или GitHub;
- **внешний ID** — идентификатор аккаунта пользователя у провайдера;
- **callback (возврат)** — переход пользователя обратно в приложение после авторизации у провайдера;
- **state** — случайный токен, связывающий начало OAuth-сценария и возврат в приложение.

## Поддерживаемые провайдеры

| Провайдер | Имя в приложении | Поле `User` |
|---|---|---|
| Google | `google` | `google_id` |
| Yandex | `yandex` | `yandex_id` |
| VKontakte | `vkontakte` | `vkontakte_id` |
| GitHub EN | `github_en` | `github_id` |
| GitHub RU | `github_rus` | `github_id` |
| Facebook | `facebook` | `facebook_id` |
| LinkedIn | `linkedin` | `linkedin_id` |

GitHub EN и GitHub RU используют разные OAuth-клиенты, но один внешний идентификатор `github_id`. Один GitHub-аккаунт не может быть связан с двумя локальными пользователями через разные клиенты.

Mail.ru намеренно не поддерживается: OAuth-клиент и маршруты для него отсутствуют, а `OAUTH_MAILRU_ENABLED` должен оставаться равным `0`.

## Настройка провайдера

По умолчанию все реализованные провайдеры выключены.

| Провайдер | Выключатель | Client ID | Client secret |
|---|---|---|---|
| Google | `OAUTH_GOOGLE_ENABLED` | `OAUTH_GOOGLE_ID` | `OAUTH_GOOGLE_SECRET` |
| Yandex | `OAUTH_YANDEX_ENABLED` | `OAUTH_YANDEX_CLIENT_ID` | `OAUTH_YANDEX_CLIENT_SECRET` |
| VKontakte | `OAUTH_VK_ENABLED` | `OAUTH_VK_CLIENT_ID` | `OAUTH_VK_CLIENT_SECRET` |
| GitHub EN | `OAUTH_GITHUB_EN_ENABLED` | `OAUTH_GITHUB_EN_CLIENT_ID` | `OAUTH_GITHUB_EN_CLIENT_SECRET` |
| GitHub RU | `OAUTH_GITHUB_RUS_ENABLED` | `OAUTH_GITHUB_RUS_CLIENT_ID` | `OAUTH_GITHUB_RUS_CLIENT_SECRET` |
| Facebook | `OAUTH_FACEBOOK_ENABLED` | `OAUTH_FACEBOOK_CLIENT_ID` | `OAUTH_FACEBOOK_CLIENT_SECRET` |
| LinkedIn | `OAUTH_LINKEDIN_ENABLED` | `OAUTH_LINKEDIN_CLIENT_ID` | `OAUTH_LINKEDIN_CLIENT_SECRET` |

Пример для `.env.local`:

```dotenv
OAUTH_GOOGLE_ENABLED=1
OAUTH_GOOGLE_ID=YOUR_GOOGLE_CLIENT_ID
OAUTH_GOOGLE_SECRET=YOUR_GOOGLE_CLIENT_SECRET
```

Выключатель работает на сервере, а не только управляет видимостью кнопки. При `*_ENABLED=0` новые сценарии входа, регистрации и привязки блокируются до обращения к провайдеру.

Реальные учётные данные не добавляются в Git. Приоритет `.env.local` и переменных Docker подробно описан в [руководстве по конфигурации](configuration.md#приоритет-переменных).

## Обычный вход и регистрация

Основные случаи удобнее рассматривать вместе:

| Ситуация | Результат | Что не происходит |
|---|---|---|
| Внешний ID уже связан | Выполняется вход в тот же локальный аккаунт | email не заменяется данными провайдера, связь не переписывается |
| Внешний ID новый, но такой email уже есть локально | Вход отклоняется нейтрально | автоматической привязки, входа в найденный аккаунт, создания пользователя и регистрационного письма нет |
| Внешний ID и email новые | Создаётся новый неподтверждённый локальный пользователь и выполняется OAuth-вход | провайдер не подтверждает локальный email автоматически, случайный пароль пользователю не отправляется |
| Провайдер не вернул email | Вход отклоняется нейтрально | пользователь не создаётся, данные не изменяются |

Если внешний ID уже связан с удалённым локальным пользователем, вход также отклоняется.

Для нового пользователя приложение сохраняет email и внешний ID, оставляет `isVerified=false`, создаёт случайный внутренний пароль и хранит только его хеш. После записи пользователя запускается обычный сценарий подтверждения email. Известный локальный пароль пользователь может установить через восстановление пароля.

Регистрационное письмо обрабатывается через Messenger `async`. В текущем Docker Compose постоянный обработчик очереди не запускается, поэтому для локальной проверки этого сценария нужно отдельно запустить `make console CMD='messenger:consume async -vv'`. Подробнее см. [раздел о почте и Messenger](configuration.md#почта-и-messenger).

Ошибки обмена OAuth-токена или получения профиля преобразуются в безопасную ошибку приложения без вывода ответа провайдера пользователю.

## Явная привязка к существующему аккаунту

Привязку начинает уже аутентифицированный локальный пользователь.

| Шаг | Что происходит |
|---|---|
| `GET` страницы привязки | Показывается форма подтверждения, данные не меняются |
| `POST` формы | Проверяются текущий пароль и CSRF-токен |
| Переход к провайдеру | В текущей сессии создаётся одноразовое намерение привязки |
| Возврат от провайдера | Проверяются пользователь, провайдер, OAuth `state` и срок жизни намерения |
| Успех | Записывается только внешний ID выбранного провайдера |

Намерение хранится в сессии не более 600 секунд и связано с конкретным пользователем и провайдером. Исходный OAuth `state` в нём не хранится: сохраняется его SHA-256-хеш. Намерение одноразовое, поэтому повторный возврат от провайдера отклоняется.

Привязка не ищет пользователя по email и не меняет текущую сессию входа. Если внешний ID уже занят другим пользователем, связь не создаётся. Последней границей защиты от параллельной записи остаётся уникальное ограничение базы данных.

## Отвязка

Отвязка тоже выполняется из аутентифицированного личного кабинета.

| Шаг | Что происходит |
|---|---|
| `GET` страницы отвязки | Показывается форма, внешний ID не меняется |
| `POST` формы | Проверяются текущий пароль и CSRF-токен |
| Успех | Обнуляется только выбранное OAuth-поле |

Поле `User` выбирается на сервере по допустимому имени провайдера. Клиент не передаёт имя метода изменения поля или произвольное имя поля.

Если провайдер выключили после привязки, пользователь всё равно может удалить уже существующую связь. Выключатель запрещает новые OAuth-сценарии, но не блокирует безопасную отвязку.

## Маршруты

Обычные OAuth-маршруты находятся под `/{_locale}`, где поддерживаются `ru` и `en`.

| Провайдер | Начало OAuth-сценария | Возврат в приложение |
|---|---|---|
| Google | `/{_locale}/connect/google` | `/{_locale}/connect/google/check` |
| Yandex | `/{_locale}/connect/yandex` | `/{_locale}/connect/yandex/check` |
| VKontakte | `/{_locale}/connect/vkontakte` | `/{_locale}/connect/vkontakte/check` |
| GitHub EN | `/{_locale}/connect/github-en` | `/{_locale}/connect/github-en/check` |
| GitHub RU | `/{_locale}/connect/github-ru` | `/{_locale}/connect/github-ru/check` |
| Facebook | `/{_locale}/connect/facebook` | `/{_locale}/connect/facebook/check` |
| LinkedIn | `/{_locale}/connect/linkedin` | `/{_locale}/connect/linkedin/check` |

Эти маршруты используются браузерным GET-сценарием, но текущая YAML-конфигурация не задаёт для них отдельное ограничение HTTP-методов на уровне Symfony Router.

Операции личного кабинета имеют явные методы:

| Операция | Маршрут | Методы |
|---|---|---|
| Привязка | `/{_locale}/profile/oauth/{provider}/link` | `GET`, `POST` |
| Отвязка | `/{_locale}/profile/oauth/{provider}/unlink` | `GET`, `POST` |

Для `{provider}` используются `google`, `yandex`, `vkontakte`, `github_en`, `github_rus`, `facebook` и `linkedin`.

## Уникальность внешнего ID

Поля `google_id`, `yandex_id`, `vkontakte_id`, `github_id`, `facebook_id` и `linkedin_id` защищены уникальными ограничениями Doctrine и базы данных. Один внешний аккаунт не может одновременно принадлежать двум локальным пользователям.
